# anti-slop-pruner · Eliminating AI-Generated Code Bloat

> **Purpose:** Detect and purge "AI slop" — redundant comments, speculative abstractions, performative docstrings, and cliché visual designs generated by automated coding assistants.

---

## 1. What Qualifies as "AI Slop"?

1. **Obvious Comments That Restate Code:**
   ```typescript
   // BAD: Slop comment restating what the code does
   // Increment counter by one
   counter += 1;

   // GOOD: Clean, self-documenting code without noise
   counter += 1;
   ```
2. **Over-Engineered Micro-Abstractions:**
   - Creating 5 layers of factories, handlers, and interfaces for a single 10-line utility function that is only used in one place.
3. **Conversational Docstring Clutter:**
   - Adding paragraph-long docstrings repeating the function name (`/** getUserById gets user by id */`).
4. **Generic AI UI Styling:**
   - Overuse of neon purple/blue glowing gradients, excessive floating cards with identical blur, and generic stock illustrations.

---

## 2. The Pruning Rules

- **Code Comments:** Only explain **WHY** an unusual decision was made (e.g., working around a browser quirk or third-party bug), never **WHAT** the code is doing.
- **Premature Generalization:** Keep code inline until it has at least 3 distinct call sites (Rule of Three).
- **Em-Dash Ban:** Eradicate AI-style em-dashes (`—`) in UI copy, replacing them with standard human punctuation (commas, parentheses, or periods).

---

## 3. Pruning Verification Command

```bash
# Detect repetitive comment noise in diffs
git diff origin/main...HEAD | grep -E "^\+\s*//\s*(Set|Get|Initialize|Create|Return|Update)" \
  && echo "Notice: Review staged comments for redundant AI restatements." || echo "Clean: No obvious comment slop."
```
